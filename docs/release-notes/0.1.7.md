# Nostr Browser 0.1.7

## Build 11

Adding a distinct NStack address now appends a connection, including when two
endpoints advertise the same Tower service identity. Re-adding the same canonical
address refreshes its existing entry. Use the address editor to explicitly move
a connection while preserving its identity and settings.

Registry mutations serialize per identity so overlapping additions, refreshes,
renames and selections retain the full saved list. Updating an entry preserves
its list position. Regression checks cover reopen/restoration, duplicate adds,
concurrent writes, browser preferences, names and backup selections using only
synthetic identities and in-memory preferences.

## NStack names and private connection displays

Saved NStacks now have local editable display names. Refresh keeps those names,
links, preferences and backup selection. Cards, workspace rows and backup summaries
show friendly names and abbreviated lowercase npubs. Legacy hostname labels use
neutral names; connections without public identity metadata show “Identity
unavailable”. Explicit connection details reveal and copy full identities and
service endpoints; the address editor remains available for troubleshooting.
Routine failure messages do not echo remote endpoint data.

Changing an address requires the complete discovered Tower service identity to
match the saved identity. Missing or different identity metadata rejects the edit
without changing saved associations. Matching workspace stable IDs, owner and
workspace service identities retain their private aliases. A changed workspace
identity receives a new alias and cannot inherit the old backup selection.
Old endpoint-specific catalogue and FIPS connection metadata are cleared on a
successful move and must be discovered again.

This uses existing HTTPS discovery metadata, without adding a key-possession
challenge or changing Suite contracts. It never derives a workspace npub from a
UUID or owner identity. Local regression tests cover persistence, identity
mismatch and screenshot-safe rendering; physical-device acceptance requires the
released build. See [NStack validation](../nstack-display-validation.md).

## Build 10

Adds Command+Right to cycle open apps/tabs with the mobile swipe’s wraparound
behavior, and Command+Left to open the side menu. Both work from the shell and
WebKit pages, including frames. Text fields, contenteditable, common app editors,
composition, and app-handled shortcuts retain their editing behavior. Mobile
gestures and Ctrl+Tab navigation are unchanged. See the
[keyboard validation procedure](../browser-keyboard-validation.md).

## Earlier changes

The login experience now displays `Nostr Browser` instead of the stale Wingman
product label. Private iOS releases also embed the canonical NBrowser repository
and exact Git commit in both signed targets so package provenance can be checked
from the archive and IPA.

Fixes `window.NStack` never becoming ready on approved HTTPS and local pages.
The page origin used to bind the injected provider was serialized with an empty
query and fragment (`https://host?#`), so the provider's exact
`location.origin` guard refused to install and sites reported the NStack bridge
as unavailable. Origins now match `location.origin` exactly; previously saved
discovery rules are read back under the canonical origin. Consent, document
binding and identity checks are unchanged.

Adds an optional local diagnostics capability for Flight Deck reports.

- Native consent permits sanitized browser evidence and limited host event
  categories in the current origin, document, unlocked identity, tab and
  workspace. Navigation, reload, background/OS lock and identity replacement revoke access.
- Saved evidence can recover after reload or restart only for the restored tab
  and matching origin, identity and workspace, after fresh native consent.
- Both individual buffers and the entire local native store are bounded to
  30 minutes and 512 KiB; abandoned contexts are pruned. Grants are never saved.
- Evidence excludes page text, bodies, headers, messages, screenshots, endpoint
  identities and arbitrary application logs. Flight Deck sends reports through
  its existing signed chat/file flow; this capability adds no network bridge.

Host evidence covers document readiness, app lifecycle transitions, main-frame
WebView resource errors and available generic transport lifecycle categories.
A 30-second native-only same-origin transition preserves load failure evidence
after browser access is revoked. WebKit content-process termination records a
bounded error and revokes the document; Android renderer termination is not
separately exposed by the current controller. It does not provide OS crash
dumps or crash-time sending. Native capability is available only where the
existing channel verifies top-level frame origin: Android, iOS and macOS.

## Validation procedure

Run Flutter analyze/tests. Build supported local artifacts, refresh the embedded
Flight Deck bundle from a verified source build, and inspect the included
version. On an explicitly authorized test device, opt in, record an error,
reload, verify fresh consent and recovery, then verify navigation, workspace
switch, lock and tab closure deny access. A native build alone does not establish
physical device acceptance or live installation.

The reusable protocol and fixtures are in
[diagnostics-protocol.md](../diagnostics-protocol.md) and
[diagnostics-fixtures.json](../diagnostics-fixtures.json).
